# 2026-11-11 上下文管理工程

- **状态**：完成
- **关联**：—
- **一句话**：建立「常驻最小路由 + 按需取用」的上下文体系，把手写文档从「知识库」降为「索引 + 代码看不见的东西」。

## 背景

项目知识散在会话里，每次新会话重复调查、重复踩坑。目标：让 Pi 每轮自动加载的窗口尽量小，细节按需取。

## 结论（调研 + 推论）

- Context engineering = **token 效用最大化**；长上下文中间段注意力衰减（lost in the middle），条目越多每条越不被遵守。
- **手写文档是负资产**：每多一行常驻文字都在稀释其他指令。所以「能代码拿到就不写」是**正确性**问题。
- 唯一值得手写：意图、硬约束、跨文件契约、**坑**（代码看起来是对的，只有踩过才知道）。
- 文档分**常青契约**（留 `docs/`）与**一次性记录**（进 `log/`）；`CONTEXT` 必须**收尾清空**，否则必腐化。
- AGENTS.md 的本质是**路由索引**，不是知识库。
- 硬约束靠文本只能提醒，护栏应交给 lint / CI / 脚本。

## 落地

- `AGENTS.md`（本文件同目录上层）：路由 + 黄金法则；根目录留一份薄引导。
- `docs/INTENT.md`：人类权威（意图 + 硬边界）。
- `docs/CONTEXT.md`：AI 执行快照（覆盖写）。
- `docs/坑与约束.md`：血泪清单（append-only）。
- `docs/log/`：本目录，`YYYYMMDD_主题.md`。

## 决策

- **不用 Pi skill 承载任务域规则**：Pi 里 AGENTS.md 常驻 + 按路由读文件已等价；skill 还多一层「描述没匹配到就不加载」的不可靠性，且关键约束（ESM `.js`）绝不能靠 skill 兜底。**skill 是多余仪式。**
- 任务域不另建 `约定/` 目录：`docs/目录与编码规范.md` 已是那篇。
- `tmp/` 用 SVN 属性（`svn:global-ignores`）而非 `.gitignore`；给 `trunk` 补属性（原先只有仓库根有）。
