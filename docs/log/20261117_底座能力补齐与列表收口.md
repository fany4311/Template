## 关键决策

- **列表抽象只收「列表那一半」**：新增/编辑表单差异太大（附件、状态机、权限树），硬抽会变成一堆 if；表单交给 `FormDialog`，有联动就继续手写。
- **主题默认值进 `sys_config`、个人偏好进 localStorage**：换浏览器保留个人选择，后台改默认值能影响新用户。
- **导入宁可报错也不静默截断**：5000 行上限 + 200 条失败明细，超限直接提示缩小范围。
- **平台级授权的判据是「码里含 `*` 或 `!`」，不是 `isBuiltin`**：部门管理员等内置角色权限为空，仍需允许配置；
  `*:*:*` / `!system:*` 只能由迁移写入，接口一律拒收（防「接口造神」）。
- **不分页 ≠ 不用抽象**：树表仍用 `DataTable` 获得统一 loading / 空态 / 列配置，只是跳过 `useCrud` 的分页语义。

## 追加：生成器增强（--menu-parent / --unique / file 字段）

- `--menu-parent /monitor`：菜单按 path 查父级，插入时写 parent_id + ancestors（父 ancestors + 父 id），
  子 route path 为「父 path + /slug」；父不存在直接抛错，不退化成根菜单。
- `--unique code`：entity 加 `@Index(unique)`、迁移加 `UNIQUE KEY`，service create/update 前置查重，
  导入失败文案区分「可能重复或超长」。
- `file` 字段：不建列，走 `sys_file` 绑定；生成 `adapters/<slug>-file.handler.ts` 并注册到 `FileBizRegistry`，
  模块 import `FileModule`；前端操作列多一个「附件」抽屉，复用新组件 `components/BizFiles.vue`
  （上传 → bind → 列表 → 解绑/下载）。
- 决策：唯一键**不含** `delete_time` —— 加了会让未删行之间不再唯一（MySQL 唯一索引里 NULL 互不冲突），
  代价是软删行仍占用键，同名重建失败；换取「未删数据真正唯一」更划算。
- 决策：附件不塞进新建表单 —— 新建时没有 bizId，绑定必然失败；改为保存后从列表行进入抽屉。
- 顺带修正 `UploadFile.vue` 的误导注释：上传接口只落 TEMP，不会自动绑定。
- 验证：临时库（建库 → 跑全部迁移 → 校验 → 回滚 → 删库）确认菜单 parent/ancestors 正确、
  UNIQUE 生效（ER_DUP_ENTRY）、down 干净；生成物在时后端 tsc 与前端 vite build 均通过，删除后全量校验全绿。
