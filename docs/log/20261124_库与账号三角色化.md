# 库与账号三角色化

- **日期**：2026-11-24
- **状态**：已完成（DDL 已执行、验证全绿）
- **关联**：无 tag
- **一句话**：库按 dev/prod/tmp 三角色重命名与分权，一库一账号落地；演练目标库固定名、备份脚本去掉危险默认值。

## 起因

库变成 4 个（`template` / `template_test` / `template_prod` / `template_gen_test`）之后，
**命名看不出角色**，且单个 `template`@`%` 账号同时授了 `template.*` 与 `template_prod.*` ——
dev 进程手里的凭据能读写生产库。派生第二个项目就没人敢动这套东西了。

## 做了什么

### 1. 三角色 + 命名规则

| 角色 | 命名 | 可丢弃 | 备份 |
|---|---|---|---|
| dev | `<项目>`（无后缀） | 可重建 | 否 |
| prod | `<项目>_prod` | 绝不 | 必须 |
| tmp | `<项目>_tmp` | 随时可 DROP | 否 |

`template_test` → `template_tmp`。tmp 类**不迁数据**（本来就该可丢弃），`db-reset.sh` 重建即可。
不再为 e2e / 生成器各开一个库 —— 共用一个 `_tmp`，串行使用。

### 2. 一库一账号

`server/sql/databases.sql` 成为库/账号/授权的单一真源；账号 `<库名>_<角色>`，只授自己的库。
三份密码互不相同，只存在 `.env`（已 gitignore），SQL 里只留 `<改我-*>` 占位符，
由 `scripts/db-apply.sh` 在 `mktemp` 渲染后执行。

> 一次失误：先把真密码直接写进了 `databases.sql`。该文件要提交并随 SVN 分发，
> 等于把密码发给所有副本。已回滚为占位符（未进过 git 历史，无需轮换）。

### 3. 两个危险默认值

- `backup.sh`：`DB_NAME:=template` —— cron 里漏传就"每天成功备份 dev 库"，生产库从未被备份。改为必填。
- `restore.sh`：只认 `DB_USER`，而它 source 的 `.env.prod` 给的是 `DB_USERNAME` → 静默退回旧共享账号。

### 4. 恢复演练改为可重建

- 目标库固定 `<项目>_tmp_restore`，**每次先 DROP 再导入**（旧行为 `<原库>_restore_<时间戳>`
  每演练一次多一个库，正是"库越变越多"的来源）。
- 目标库必须是 `*_tmp` / `*_tmp_restore`，否则要 `--force`。
- 建库/删库/授权需管理员连接（一库一账号后业务账号建不了库）：`MYSQL_ADMIN` →
  `MYSQL_ROOT_PASSWORD` → 自动发现 mysql 容器，三级回退；密码走 `MYSQL_PWD`，不进 argv。
- **导入前剥掉 dump 里的 `CREATE DATABASE` / `USE`**：`mysqldump --databases` 会把源库名写进
  SQL 流，原样灌会写回源库 —— 演练"成功"但目标库 0 张表，最坏情况把生产库原地覆盖一遍。

## 验证

- `db-apply.sh` 幂等重跑通过；`SHOW GRANTS` 逐账号核对，只有本库。
- `db-reset.sh --yes` 重建 `template_tmp` 并跑完迁移（基线 `CreateCoreSchema` + 全部 seed）。
- 恢复演练：造 dump（16K）→ 建 `template_tmp_restore` → 导入 19 表 / 5 用户 / 5 角色 →
  源库 `template` 19 表 5 用户未受影响 → 删演练库。
- `scripts/verify.sh` 全绿；dev 三进程 online；`/health/ready` 数据库 up。
- 闸门回归：`db-reset.sh --db template_prod` exit 1；`restore.sh --db template_prod` exit 1。
