## 1. 为什么去掉版本控制叙述

版本控制工具的选择属于**使用者个人习惯**，不该写进项目文档，更不该写进派生流程。
原文档里有三类问题：

1. **纯叙述**：`AGENTS.md` / `INTENT.md` 要求「提交前先更新工作副本」。
2. **路径错误**：命令里多写了一层目录名（如 `cd <多余的一层>/server`）共 5 处 ——
   仓库根就是当前目录，照文档敲会 `No such file or directory`。
   这是从版本控制工作副本迁到本地目录时的残留。
3. **强制依赖**：`deploy/rename.sh` 强制要求某种版本控制工具，否则直接退出 ——
   等于「不装它就不能派生项目」。

## 2. 改法

| 类别 | 处理 |
|---|---|
| 叙述性提及 | 全部改为中性表述：「复制基线副本派生」「随底座副本分发」「不入库的 .env」 |
| 路径错误 | 命令里的多余目录层去掉（文档 5 处 + 代码注释 2 处） |
| `rename.sh` | 版本控制改为**可选**：有才做「工作区干净」检查与改名保留历史；没有就警告后继续用普通 `mv`。rename 本身不依赖它 |
| 变量名 | `ecosystem.dev.config.cjs` 的 `TRUNK` → `ROOT`（与 `template.sh` 的 `ROOT` 一致） |
| `docs/log/` | **不动**。append-only 历史记录，改写会让“当时做了什么”失真 |
