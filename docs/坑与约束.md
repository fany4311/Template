# 坑与约束（血泪清单）

> **代码里看不见的东西**：看起来是对的，只有踩过才知道会炸。
> 规则：只增不删；**已修复且不再可能复发的**，压成一句规则，或移进 `docs/log/`。
> 写成一句可照做的规则，而不是一段排查故事。

---

## ESM / 构建

- 相对导入必须带 `.js` 后缀（`nodenext`），否则 TS2835。
- 禁 `src/...` 路径别名；`__dirname` 用 `import.meta.dirname`；内置模块加 `node:`。
- PM2 跑 Vite 必须指 `node_modules/vite/bin/vite.js`。
- dev Vite 必须加 `--strictPort`（防止端口漂移，同机共存前提）。

## 数据库 / 迁移

- **迁移按类名判重，不按 timestamp**：换号（改名）等于新迁移。
- 已跑迁移**不可改**，修正一律追加；新库必须补基线迁移（`CreateCoreSchema`）。
- `DB_SYNCHRONIZE=true` 与迁移并存 → synchronize **抢先改表**，迁移 DDL 从未生效。三份 `.env` 一律 `false`。
- 迁移 DDL 必须幂等：`hasColumn()` / 查 `information_schema` 后再 ALTER。
- 迁移目录 `dist` 与 `src` 并存，`migration:run` 实际走 `dist/`。
- MySQL 一张表只允许**一个自增列**，且 DDL 隐式提交。
- `docker exec mysql -e` 多表 DELETE 必须 `-D` 选库。
- **一库一账号，禁止跨库 GRANT**（定义在 `server/sql/databases.sql`，台账 `docs/库台账.md`）。
  账号 `<库名>_<角色>` 只授自己的库 —— 否则 dev 进程手里的凭据能读写生产库。
- **MySQL 跑在 Docker 里时账号 host 必须写 `%`**：连接来源是 docker 网关（172.x），
  写 `127.0.0.1` 会 `Access denied`，很容易误判成密码错。边界靠一库一账号，不靠 host。
- **真密码不许写进被分发的 SQL**：`databases.sql` 只留 `<改我-dev|prod|tmp>` 占位符，
  真密码只落各自的 `.env`；`db-apply.sh` 用 `mktemp` 渲染后执行、退出即删。
- **业务账号建不了库**：`GRANT ALL ON <库>.*` 不含 `CREATE DATABASE`。
  `restore.sh` / `db-reset.sh` 要用管理员连接（`MYSQL_ADMIN` / `MYSQL_ROOT_PASSWORD`）。
- **外键：有意不加**（已拍板）。软删让 FK 永远满足、批量删除顺序会变成隐式契约
  （MySQL 不支持延迟约束）、派生项目要做数据手术。补偿：应用层「有引用就拒删」+
  关联表唯一索引，孤儿巡检 SQL 见 `docs/部署端环境.md`。

## TypeORM / 实体

- **联合类型字段必须显式 `type`**（否则元数据推断错）。
- `level` 无数据库默认值：绕过 `RoleService` 直接 `repo.save(Role)` 必须自己给 `level`。
- `allocateLevel()` 两处 `withDeleted()` 不能省（否则软删角色会撞唯一约束）。
- **软删 + 单列唯一 = 删了建不回来**：唯一键只含业务列时，软删行仍占着值 →
  重建同名 `1062`，而 `findOneBy` 因软删过滤查不到它 → 界面只报「数据库操作失败」。
  正确写法：唯一键含 `delete_time`（NULL 不参与比较 → 活行唯一、墓碑行可重复），
  见 `sys_file` 与迁移 `1767000024000`。改索引别写死 TypeORM 的哈希索引名（派生项目会变）。
- **删部门必须先查挂人**：`sys_user.dept_id` 没有外键，删完 `dept_id` 悬空 → dataScope
  静默失权。`DeptService.remove` 已堵（有用户拒删），与 `RoleService`（有持有人拒删）对称。

## 权限

- 接口（DTO）只收**具体权限码**；`*` / `!` 只由迁移/seed 写。
- **权限串混用不可判定**：`*:*:*` 必须独占。
- 权限匹配有**三份副本**（后端权威 + `web_admin` + `web` 最小壳），必须同源：
  `server/src/common/authz/permission.util.ts`、`web_admin/src/utils/permission.ts`、`web/src/utils/permission.ts`。
  一致性由 `server/test/unit/permission-util.spec.ts` 的**对照单测**钉住（同时 import 三份实现）。
  **新增匹配分支时先改那张用例表**，表红了再补三份实现。
- 权限清单**不参与鉴权**：`RbacGuard` 只看 `sys_role.permissions`；清单为空不影响鉴权。
- **含 `*` / `!` 的角色，界面权限区必须只读**（如校级管理员 `*:*:*,!system:*`）。
  判据用「权限串里有没有 `*` 或 `!`」，**不要用 `isBuiltin`** —— 部门管理员、业务操作员、
  审计员同为内置角色、权限为空，必须允许配置。

## 配置 / 安全

- **`req.ip` 默认不可信**：不配 `trust proxy` 时恒为 127.0.0.1。后果：限流按 IP 计数 →
  **全校共用一份配额**；审计 / 登录日志 IP 全同 → 出事查不到人。
  修法：`setup-app.ts` 设 `trust proxy = TRUST_PROXY`（缺省 1 = Nginx 一层）；Node 直连对外才填 `0`。
- **限流键 = IP + 路由**，不是「IP + 全局」。前提仍是上一条的 IP 可信。
- **e2e 必须关限流**（`.env.test` `THROTTLE_ENABLED=false`），否则同 IP 高频登录随机 429。
- **`new HttpException('msg', 状态码)` 的 `getResponse()` 是裸字符串**，而内置异常走
  `createBody` 生成对象。全局过滤器必须在这一支回写 `code`，否则 HTTP 429/403 但
  `body.code=500`。回归：`test/unit/exception-filter.spec.ts`。
- **环境变量校验在启动时执行**（`env.validation.ts`）：prod 拒绝 <32 字符或模板值的
  `JWT_SECRET`、拒绝 `DB_SYNCHRONIZE=true`。校验失败 = 进程起不来，**有意为之**。
- **dev / prod 必须真正隔离**：`JWT_SECRET`、`DB_DATABASE`、`REDIS_DB` 三样都要分开。
  只改端口不叫隔离 —— 共库/共密钥下 dev 会串到 prod（会话互踢、数据互相覆盖）。
- **Swagger 生产默认关闭**（`SWAGGER_ENABLED`，缺省 `NODE_ENV !== 'prod'`）：
  `/api/docs-json` 是完整接口 + 参数清单，匿名可读 = 免费的攻击地图。
- **审计 `detail` 由拦截器统一写 + 统一脱敏**（默认记入参，`@Auditable({ capture: false })` 可关）。
  脱敏是拦截器里的黑名单（password/secret/token/captchaCode…），别指望每个接口自己排除；
  Buffer 转 `[binary]`，超 2000 字符截断（否则一个附件上传就能把 `detail` 写爆）。
- **账号侧能力底座不预置**：没有按账号失败锁定、没有密码复杂度、验证码默认关。
  部署端必查清单见 `docs/部署端环境.md`「账号与登录安全」。别把某单位的口令规则写进机制层。

## Zod / DTO

- **Zod 4 `.partial()` 保留内层 `.default()`** → PUT 退化为整条覆盖；必须用 `updateSchemaOf()`（`src/common/dto/update-schema.util.ts`）。
- 时间字段用 `z.iso.datetime()`；查询空串 = 未填（`z.preprocess` 归一）。
- 单测里 `Reflect.defineMetadata` 必须先 `import 'reflect-metadata'`。

## 树形数据（dept / menu）

- **改子孙 `ancestors` 必须带逗号边界**：`LIKE '0,1%'` 会误伤 `0,10`（id=1 的**兄弟**子树），
  而 `ancestors` 正是数据范围求子树的依据，权限跟着错。
  正确写法 `(= :p OR LIKE :pc)`，`pc = '${oldPrefix},%'`。回归：`test/dept-tree.e2e-spec.ts`。
- **`parentId` 要能表达「移到顶级」**：`z.coerce.number().int().positive()` 会把 `null`/`''`
  强转成 `0` 再被拒，结果是**节点一旦挂下去就永远搬不回根**。
  统一用 `common/dto/parent-id.util.ts` 的 `parentIdSchema`；`.optional()` 在**外层**。

## 响应包装

- **不可用「返回体有没有 `code` 字段」判断是否已包装**：自带 `code` 列的业务对象
  （单据编号 / 字典编码 / 行政区划码）被单详情接口直接 `return` 时会**静默少包一层**，
  前端拿到 `{code,...}` 而 `data` 是 `undefined`。想自定义 `msg` 就显式 `@Keep()` + `return success(...)`。
  回归：`test/unit/transform.interceptor.spec.ts`。

## 前端

- **「没权限」不能表现成 404**：侧边栏用 `/menu/routes`（按权限过滤），**路由注册必须用
  `/menu/pages`（不过滤）**。否则无权限地址在路由表里不存在 → 命中 catch-all → 渲染 404，
  用户以为页面没了。现在全量注册 + 守卫读 `meta.perm` → 403；真不存在的仍是 404。
- **空壳目录也会 404**：菜单 M 类型 `perms` 是空串。规则：**目录不单独判权限，只能由
  「有命中权限的后代」通过祖先链带进来**；侧边栏只把 `type==='C'` 渲染成可点项。
- `crypto.randomUUID` 有安全上下文限定 → 用 `getRandomValues` 自拼 UUID v4。
- `ElTree` 的 `filter-node-method` 类型是 `TreeNodeData`，自定义节点需 `Record<string, unknown>` 再取值。
- 业务异常走 HTTP 200 + `body.code`；前端 catch 判 `error instanceof ApiError`。
- **列表页写法固定**：`useCrud` + `DataTable` + `FormDialog`。表单有联动或自定义控件
  （权限树、部门树选择）时继续手写弹窗，别硬塞配置。树表整棵返回、无分页，**不套 useCrud**。
- e2e 里 `POST` 需 `Idempotency-Key` 请求头。

## 部署 / 运维

- **迁移里混了演示数据**：`SeedHazardDemo` 在 `up()` 开头按 `NODE_ENV=prod` 短路
  （**不是**靠注释提醒）。派生项目要自带 seed，照这个写法在环境上断开，别指望人工记得删。
- **权限清单是反射来的，只看得见路由上的 `@RequiresPermissions`**：只在 service 里消费的码
  （如 `system:file:remove`）不登记进 `permission-catalog.ts` 的 `EXTRA_PERMISSIONS`
  就永远进不了 `sys_permission` → 角色界面勾不到 → 这条能力永远无法授予，且不报错。
- `template.sh stop` 会摘 nginx 软链 → 端口无监听（预期行为，非故障）。
- **prod 必须显式传 `NODE_ENV=prod`** 跑 `migration:run`；换独立库名后必须先建库 + 跑迁移再启动。
- **外部连接必须显式关，否则进程永远不退出**（Redis / 存储 / 定时器 / 子进程）：
  ioredis 的 socket 是活跃 handle —— 不关的话 `authz-sync` 跑完不退、`template.sh` 卡住、
  SIGTERM 优雅停机名存实亡。修法：`OnModuleDestroy` → `quit()`，带兜底 `disconnect()`。
  回归：`test/unit/redis.service.spec.ts`。**新增外部连接一律问「谁在退出时关它」**。
- Nginx 不占 80；`client_max_body_size` 三层对齐（20m ↔ `MAX_FILE_SIZE` 10MB ↔ 前端）。
- `authz:sync` 在 pm2 重载前跑，**失败只 warn 不阻断**。
- **恢复演练的目标库必须固定名**（`<项目>_tmp_restore`，先 DROP 再导入），不要每次加时间戳
  —— 否则几轮下来库表散落，谁都不敢 DROP。
- **`mysqldump --databases` 的 dump 里带 `USE <源库>`**：原样灌会**写回源库**（目标库 0 表）。
  `restore.sh` 已剥掉 `CREATE DATABASE` / `USE`；手工导入先确认 dump 形态。
- **备份脚本不能给库名默认值**：`backup.sh` / `restore.sh` 的 `DB_NAME` / `DB_USER` 都 `:?` 必填
  —— 有默认值就会「每天备份成功，而生产库一次没备」。

## 定时任务 / 数据回收

- **新写定时清理任务，三件事必须都有**（照 `file.cleanup.task.ts` 抄）：
  1. `app.env === 'test'` 直接 `return` —— e2e 会断言表内容，后台任务删一行就是随机红；
  2. `running` 重入闩 —— 上一轮没跑完就跳过；
  3. `try/catch` 吃掉异常 —— `@Cron` 回调里抛出去会把进程带崩。
- **清理只动终态，永不动物流中间态**：`sys_outbox` 只删 `sent`/`failed`。
  **例外：`sys_idempotency` 按 `expire_at` 删** —— 那里的 `processing` 只是占位，
  进程崩了会留下永不释放的占位，按过期回收正是它的自愈机制。
- **保留期按 `create_time` 算，不按 `sent_at`**：`failed` 事件永远没有 `sent_at`。
  索引建成 `(status, create_time)`，否则每小时回收都退化成全表扫。
- **幂等占位冲突必须有限重试**（现为 3 次上限 + 退避 + `ApiException(409)`）：
  递归重试的深度由并发度决定，高并发下是栈溢出而不是可预期的 409。

## 密码 / 会话

- **改密必须使会话失效**：旧 token 能用到 TTL 到期，改密就是自我安慰。
  副作用：改密人自己也被踢下线，前端据此跳登录页。
- **管理员重置不要求原密码**：权限边界靠 `system:user:reset-pwd`，不靠「他知道旧密码」。
- **密码策略单点**：`auth/dto/password.dto.ts` 的 `passwordSchema` 同时被「创建用户」与
  「改密/重置」引用。各写一份的结果是“建账号能过、改密过不了”，前端提示也对不上。

## 数据范围（dataScope）

- **调 `dataScope.resolve()` 时直接传 `user`，不要手搓 `{ userId, deptId }`**：
  手搓会把 `dataScopeDepts` 丢掉，而 `CUSTOM` 的空集合语义是 **fail-closed** ——
  表现不是报错，是"这个角色什么都看不到"。
- **CUSTOM 的部门集合进会话，不进 JWT**：JWT 只放 userId/username（否则改权限要等 token 过期）。
  改了角色的部门集合要**失效持有人会话**。
- **空集合 = 不可见**，绝不退化成"不过滤"。界面拦空提交，接口也允许空（两段式操作需要），
  所以这条兜底必须在查询层。

## 审计

- **`AUDIT_MODE=sync` 不等于「审计与业务同事务」**：审计写在自己的连接上、业务事务已提交，
  失败回滚不了业务 —— 这是 append-only 审计的固有取舍。`sync` 买到的只是「延迟和失败可见」。
- **审计拦截器不能用 `tap` 做同步等待**：`tap` 的副作用回调不 await Promise，
  在那里 `await` 只是「语法上当等了」的假同步。要等就用 `mergeMap` / `concatMap`。
- **审计最终失败必须把完整条目打进日志**：只记 `action + traceId` 等于
  「知道丢了一条，但不知道丢的是什么」，事后无法重建。
