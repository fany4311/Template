# 库台账

> **只写「为什么这么分」和「现在有哪些库」。**
> 可执行的 DDL（库名 / 账号 / 授权）在 `server/sql/databases.sql` —— 那是单一真源，本文件不重复抄。
> 改名、加库、派生的具体动作见文末「变更流程」。

## 1. 为什么是三个角色

库变多的真实痛点不是「数量」，是**没有角色**：`template` / `template_test` / `template_prod` /
`template_gen_test` 四个库，语义其实是三类（开发 / 终态 / 一次性），命名却看不出来。
派生第二个项目之后就没人敢动了。

所以先定角色，再定名字：

| 角色 | 语义 | 命名 | 可丢弃？ | 备份 | 迁移 |
|---|---|---|---|---|---|
| `dev` | 开发主库，含 4 个演示账号与演示隐患单 | `<项目>`（**无后缀**） | 可重建 | 否 | 必须齐 |
| `prod` | 终态数据，只增不删 | `<项目>_prod` | **绝不** | 必须 | 必须齐 |
| `tmp` | 一次性：生成器验证 / e2e / 恢复演练 | `<项目>_tmp` | 随时可 DROP | 否 | 跑一遍即可 |

**dev 故意不带后缀**：它是派生模板的默认身份（`.env.dev` 的 `DB_DATABASE=template`），
带后缀会让「默认库」变成例外。规则因此读作：**prod 加 `_prod`，tmp 加 `_tmp`，dev 就是项目名**。

**`tmp` 一个项目只要一个。** 之前的苗头是给 e2e 单开 `template_e2e`，给生成器单开
`template_gen_test` —— 各占一个库名，谁都不敢删。它们同类：需要干净、会写入、可丢弃。
共用一个 `_tmp` 库、**串行使用**（跑前 `db-reset.sh` 重置）就够，库数不随测试方式增长。

## 2. 现在的库（2026-11-17）

| 库 | 角色 | 账号 | Redis DB | MinIO bucket | 谁在用 |
|---|---|---|---|---|---|
| `template` | dev | `template_dev` | 1 | `template` | `server/.env.dev`，dev 三进程 |
| `template_prod` | prod | `template_prod` | 4 | `template` | `server/.env.prod`，PM2 单实例 |
| `template_tmp` | tmp | `template_tmp` | 2 | 内存盘（`STORAGE_DRIVER=memory`） | `server/.env.test`，e2e / 生成器 / 恢复演练 |

- Redis 索引、bucket 与库按同一套角色对应，**一个角色一套，不共用** —— 共库或共密钥时
  dev 的操作会串到 prod（会话互踢、事件被抢），见 `坑与约束.md`。
- 密码不落本文件（`docs/` 随底座副本分发给派生项目）。三份密码存在各自的 `.env` 里，互不相同。

## 3. 一条铁律：一库一账号

旧写法是单个 `template`@`%` 同时 `GRANT ALL ON template.*` 与 `template_prod.*`，
于是 **dev 进程手里的凭据能读写生产库**。这把「隔离」从数据库层降级成了自觉。

现在是 `<库名>` ↔ `<库名>_<角色>` 一一对应，只授自己的库。代价是一份 `.env` 多一行，
收益是生产库对 dev 进程**物理不可达**。

## 4. 变更流程

**加一个库**（只该发生在派生新项目时）
1. 在 `server/sql/databases.sql` 追加该项目的三段（库 / 账号 / 授权），**不要改本项目的段落**
2. `bash scripts/db-apply.sh`（幂等；它从三份 `.env` 取密码渲染，SQL 里只留占位符）
3. 本文件 §2 表格加一行
4. `.env` 填新账号密码

**重置 tmp 库**（e2e 前、生成器验证、恢复演练）
```bash
bash scripts/db-reset.sh              # 默认 template_tmp，会要求确认
bash scripts/db-reset.sh --yes        # 无人值守
```
一条命令做完：DROP → CREATE（utf8mb4_unicode_ci）→ 授权 → `migration:run`。
这段以前靠人在 `本地环境.md` 和 `部署端环境.md` 里各抄一遍 `docker exec ... CREATE DATABASE`，
现在只有一处，且字符集不会再抄错。

**恢复演练**
目标库固定 `<项目>_tmp_restore`（tmp 类，先 DROP 再导入），演练完可删，下次重建。

**改名**
tmp 类库直接走 `db-reset.sh`（不迁数据）；`prod` / `dev` 改名要 dump + restore，
**非必要不做** —— 名字错不致命，丢数据致命。

**项目归档 / 回收**
台账加一列「状态 ∈ 活跃 / 归档 / 待删」。归档项目**只保留 `_prod`**（备份还在），
连同库一起回收的是四样：MySQL 库、Redis 索引、MinIO bucket、PM2 进程名。
只删库不删其余三样，等于埋一颗「同机共存」的雷。
