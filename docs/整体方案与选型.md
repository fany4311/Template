# 整体方案与选型

> 只写**决策与理由**（代码里看不到的）。目录 / 接口 / 字段 / 迁移用 `codegraph_*`、
> `web_admin/openapi.json`、`sys_permission` 现场取；建设流水见 `log/`。

## 1. 定位与范围

- 省内高校「校内自建安全管理平台」＝ **通用底座** + 省平台对接通道。
- 本期只做**通用系统骨架**（跑得通、可派生），业务按切片推进；**底座不含任何业务名词**。
- 两条主线：
  - **北上**：隐患/风险/整改台账 → 标准化摘要 → 省平台（定时全量 + 增量实时 + 失败告警 + 同步日志）。
  - **内管**：一线巡查 → 部门初审 → 校级复核/终审 → 销号，全程留痕、权限分层、原始材料本地留存。
- 派生：底座打 tag，新项目 `svn copy` 副本改，**不从零起**（见 `init.md`）。

## 2. 技术基线

- 后端 Node 24 + pnpm + **NestJS 12 + ESM**（`.ts` 源，`nodenext`）+ Zod 4 + TypeORM + argon2。
- 前端 Vue 3 + Vite + Element Plus，**静态托管**。
- 异步：进程内 `@nestjs/event-emitter` + Transactional Outbox，**暂不引入 MQ**。
- 可观测：**当前只有 pino 日志**（dev 彩色 / prod 滚动文件）。
  OpenTelemetry（指标 / 链路 / 日志，OTLP → 自建 Collector）是**目标设计，尚未实现**。
- 测试 / Lint：**Vitest + oxlint**（ESM 工程默认；Jest 在 ESM + Nest12 下配置繁琐）。
- 版本基线：前后端退回「上一代成熟主版本」；**严禁自改依赖版本**。

> ### ⚠ 目标设计 vs. 已实现（派生项目必读）
>
> 本文档多处描述的是**目标架构**。下表列出「文档里写了、代码里还没有」的三项 ——
> 部署/派生时**不要以为已经具备**：
>
> | 能力 | 文档承诺 | 代码事实 | 缺失后果 |
> |---|---|---|---|
> | 链路/指标可观测 | 生产自建 OpenTelemetry（OTLP → Collector） | `grep -rn "otel\|opentelemetry" server/src server/package.json` **零命中**；无任何 OTel 依赖 | 没有分布式链路、没有指标暴露；排障只能看日志 |
> | 字段级加密 | 敏感字段 AES-256-GCM | 无实现（仅 S3 传输侧 SSE `AES256`） | 库被读走 = 明文；靠 DB 账号权限兜底 |
> | PII 脱敏 | 敏感入参写审计 `detail` 前脱敏 | 无脱敏器；`AuditInterceptor` 原样记录入参 | 审计表里可能落明文手机号/身份证 |
>
> 这三项均为**有意的未落地**（留待业务触发时实现，避免为未知需求先造抽象）。
> 实现时应作为独立能力进底座，并在本节把它从表中删除。

## 3. 分层选型

| 层 | 关注点 → 选型 |
|---|---|
| 接入契约 | OpenAPI（Zod Standard JSON Schema）、URI 版本化 `/api/v1`、`errorCode` + `traceId`、`nestjs-cls` 贯穿上下文、限流 |
| 业务权限 | **CASL 单引擎**（RBAC + ABAC + ReBAC-lite）、显式 `UserRole`（含临时授权）、`dataScope`、审计 |
| 一致性 | TypeORM 事务（`@Transactional` + CLS）、**Outbox** + 乐观锁、`@Idempotent` |
| 数据安全 | 软删 + 保留策略、`argon2id`、备份 + 恢复演练（**已实现**）；字段级 AES-256-GCM、PII 脱敏（**未落地**，见 §2 警示表） |
| 文件存储 | `@nestjs/storage`（s3/local/memory 可拔插）+ 自研元数据/多态绑定/权限/回收（见 `文件与附件.md`） |
| 运行保障 | pino 日志 + Terminus 健康检查 + PM2 + Nginx（仅内网、无域名）；OTel 链路/指标**未落地** |

## 4. 关键取舍（已定，别重复讨论）

- **不用 `@nestjs/observe`**：它是 SaaS APM（数据上报第三方），涉师生个人信息与校园安全数据，故定位为自建 OTel（**目标，尚未落地**）。
- **CASL 单引擎**统一 RBAC + ABAC + ReBAC-lite，预留 `PolicyPort` 便于将来换 OpenFGA；
  系统管理域（user/role/dept）只用权限码，`@CheckPolicies` 留给业务资源。
- **Outbox 先进程内**：可靠投递与跨聚合一致性够用；将来换 MQ 只替换投递实现。
- **Redis 6 兼容**（部署端是 Redis 6）：限流 / 缓存 / 锁只用 6 兼容命令。
- **自研 `@Transactional` / `@Idempotent`** 基于 CLS，见 `横切地基-事务与审计.md`。

## 5. 后端分层（六边形，契约）

```
server/src/{core,common,modules,share}
```

- `core/` 基础设施（config / logger / database / redis / storage），**无业务语义**。
- `common/` 横切（decorators / guards / interceptors / filters / dto / entities / authz）。
- `modules/` 按域划分；模块内按需收敛 `domain / application / infrastructure / interfaces`。
- 领域层**不依赖 Nest / ORM 装饰器**，基础设施细节走端口注入。
