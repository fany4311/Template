# 目录与编码规范

> 适用 `trunk/server`（NestJS 12 + ESM）。核心原则见根 `AGENTS.md`：尊重 Nest 12、少耦合、可拓展。
> **目录树用 `codegraph_files` 现场取**；本文件只记**命名与编码契约**。

## 1. 分层约定

```
server/src/{core, common, modules, share}
```

| 目录 | 职责 |
|---|---|
| `core/` | 基础设施（config / logger / database / redis / storage），**无业务语义** |
| `common/` | 横切（decorators / guards / interceptors / filters / dto / entities / authz） |
| `modules/` | 业务模块，按域划分 |
| `share/` | 跨业务共享 service |

业务增长时，模块内部按 `domain / application / infrastructure / interfaces` 四层收敛：
domain 不依赖 Nest / ORM 装饰器，基础设施细节通过端口（interface）注入。

## 2. ESM 铁律（Nest 12 强制）

| 规则 | 说明 |
|---|---|
| 相对导入必须带 `.js` | `import { X } from './x.js'`（源是 `.ts`，import 指编译产物）。**省不得**（TS2835） |
| 禁 `src/...` 路径别名 | ESM 运行时不认；一律相对路径 |
| `__dirname/__filename` | 用 `import.meta.dirname` / `import.meta.url` |
| 内置模块加前缀 | `import { randomUUID } from 'node:crypto'` |
| 只当类型的导入 | `import type { X }`（避免运行时导入不存在的绑定） |
| CJS 包 | 默认导入可能拿到命名空间：ioredis 用 `import { Redis } from 'ioredis'` |

## 3. 校验：Standard Schema（Zod）

- **DTO = schema**：`export const xxxSchema = z.object({...}); export type XxxInput = z.infer<typeof xxxSchema>;`
- 路由参数经装饰器 `schema` 选项绑定：`@Body({ schema: loginSchema })`、`@Query({ schema })`、`@Param('id', { schema: z.coerce.number().int().positive() })`。
- 全局只挂 `StandardSchemaValidationPipe`；未声明 schema 的参数原样放行。
- 环境变量校验同样用 Zod（`core/config/env.validation.ts`）。
- 命名：文件 `xxx.dto.ts`，schema `xxxSchema`，类型 `XxxInput` / `XxxQuery`。

## 4. 命名约定

| 对象 | 约定 | 例 |
|---|---|---|
| 文件 | kebab-case + 类型后缀 | `user.service.ts`、`jwt-auth.guard.ts` |
| 类 | PascalCase + 后缀 | `UserService`、`RbacGuard`、`AllExceptionFilter` |
| 权限码 | `域:资源[:动作]` | `system:user:list` |
| Redis key | `前缀:...`，集中在 `common/constants/redis.constant.ts` | `auth:token:{userId}` |
| 数据库表/列 | 蛇形 | `sys_user`、`create_time` |
| 环境变量 | 大写下划线 | `DB_SYNCHRONIZE` |

## 5. 工程命令

```bash
pnpm start:dev | build | start:prod | lint
pnpm format | format:check                      # oxfmt
pnpm test | test:e2e
pnpm migration:generate | run | revert | show   # 迁移（先编译再执行）
```

**工具链归属**（三个子项目一致，别各自发挥）：

| 事 | 用什么 | 说明 |
|---|---|---|
| 检查 | `oxlint` | 后端 `--type-aware`（tsgolint）；前端只看语法/常见错 |
| 格式化 | `oxfmt` | 配置 `.oxfmtrc.json`（单引号 / trailingComma all / printWidth 80）。**prettier 已移除**，一个仓库只留一个格式化器，否则两人格式化会互相打架 |
| 类型 | `tsc` / `vue-tsc` | 后端 `tsc --noEmit`；前端只能 `vue-tsc`（SFC 里的类型只有它能看） |
| 单测 | `vitest` | |
| E2E | `playwright` | 需要跑着的 dev 环境；浏览器要 `npx playwright install chromium` |

## 6. 响应契约（强制）

- 每接口必须带 `@ApiOkZod('组件名', dataSchema, '说明')`；**只描述 `data`**，包络自动补。
- 响应 schema 放 `dto/*.response.ts`；组件名即前后端契约名，同名必须同结构。
- 新增接口同步补 `test/contract.e2e-spec.ts` 契约断言。
- 前端响应类型由 codegen 派生，**不得手写响应结构**。

## 7. 纪律

- 改完先报告，不自动提交。
- 新增业务模块三步：`modules/xxx/` 建模块 → `app.module.ts` 注册 → 接口加权限码。
- 生产禁用 `DB_SYNCHRONIZE`，一律走迁移。
