# 通用底座：范围与冻结点

> 底座**只做机制，不做业务**；**不追求"完全通用"**，够用 + 副本友好即可。

## 1. 一句话结论

不要现在冻结，也不要追求"完全通用"。
**最佳冻结点 = 地基 + 通用管理域 完成，且被「一条真实业务闭环」验证过之后**，再抽离打 tag。

理由：抽象正确性只有被真实业务用过才知道；未验证就冻结几乎必然抽象错，代价远大于多走一步。

## 2. 边界

### 进底座（机制 / 通用能力）

| 层 | 内容 |
|---|---|
| 框架层 | config、logger、db、redis、cls、health、异常、版本化、安全头、限流、优雅停机（`otel` 未落地，暂不在此行） |
| 横切层 | 认证(JWT)、RBAC+ABAC+ReBAC、审计、事务·幂等·Outbox、事件、文件、字典、通知、定时、导入导出 |
| 通用管理域 | 用户、角色、权限、部门、菜单、字典、参数、操作日志、登录日志、文件、同步日志、任务调度 |
| 前端壳 | 登录、布局、菜单、权限指令、CRUD 生成器、字典组件 |
| 运维与规范 | pm2、nginx、migration、backup、发布回滚 + 目录规范 / 错误码表 / 契约 |

### 不进底座（必须留在业务侧）

- 具体业务实体与流程（隐患、应急、演练、危化品…）
- **省平台 / 第三方适配**（每个项目都不同）
- 具体报表、大屏
- 具体权限码集合（底座只给**机制**，不给**策略**）

> 硬纪律：**底座里不允许出现任何业务名词**，出现即抽象泄漏。

## 3. 冻结点

```
①幂等+Outbox ──②CASL权限+通用管理域 ──③第一条业务闭环(隐患) ──✂️抽离──▶ Csmu_Base v1.x
                                                      ↑
                                             在这里才冻结（已被业务验证）
```

- ❌ 现在冻结 → 抽象未验证，必返工
- ✅ 第③步跑通后 → 剥离业务切片 → 打 tag

## 4. 保存形态

**独立 SVN 仓库 + tag 版本化 + 副本派生**：`svn copy ^/.../tags/vX ^/NewProject/trunk`。

- ❌ 不用 `svn:externals`（与副本修改冲突、耦合难拆）
- ❌ 不做「微内核 / 插件引擎」（过度设计，通用系统最常死于此）

## 5. 让「副本改」不失控的两个抓手

1. **扩展点文档化**：每个机制都写「如何新增一个业务模块」（模块注册、权限码、错误码、事件名）。
2. **脚手架生成器** —— **已落地**：`pnpm gen:module <slug> --label "名称" --field "title:string:标题,content:text:内容"`
   一次生成后端 CRUD（含导出/逐行导入）+ 建表与菜单迁移 + 前端列表页（DataTable / FormDialog / ImportDialog）。
   生成后仍需 `pnpm authz:sync`（权限码）、`pnpm migration:run`（建表+菜单）、人工给角色授权。
   `--dry-run` 只列文件；目标已存在会拒绝；字段类型：string / text / int / decimal / bool / datetime / dict:<类型> / file。
   - `--menu-parent /monitor`：菜单挂到已存在的父菜单下（按 path 查，不存在直接报错，不静默退化成根菜单），
     子菜单 path 为 `父 path + /slug`、ancestors 沿父链续写。
   - `--unique code`：该字段建唯一键（entity `@Index` + 迁移 `UNIQUE KEY`），服务层 create/update 前置查重给出人话提示。
     注意软删：唯一键不含 `delete_time`，软删行仍占用键，同名重建会失败（需要就先恢复原行）。
   - `file` 字段：**不建列**，走 `sys_file` 多态绑定。生成器额外产出 `adapters/<slug>-file.handler.ts`
     （注册到 `FileBizRegistry`）、模块里 import `FileModule`、前端操作列加「附件」抽屉（`BizFiles` 组件）。
     新建记录时没有 id，附件要在保存后从列表行进入。

## 6. 冻结门槛（v1 验收）

- [ ] 不改底座代码，即可加出「带权限 + 审计 + 分页 + 导入导出 + 文件」的 CRUD 模块
- [x] 一条业务闭环端到端跑通（事务 + 审计 + 权限 + 幂等全生效）
- [ ] `pm2 + nginx + migration + 备份` 有**可执行**脚本（非模板）
- [ ] 前端壳能登录并按权限显示菜单
- [ ] 底座内无任何业务名词
