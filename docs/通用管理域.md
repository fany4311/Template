# 通用管理域

> 底座机制，**不含业务名词**。派生后直接复用，只往里加菜单与权限码。
>
> 接口清单 → `web_admin/openapi.json`；权限码清单 → `sys_permission`（`pnpm authz:sync` 落库）。
> 本文件只记**机制与约定**。

## 1. 模块与表

| 模块 | 表 | 说明 |
|---|---|---|
| 菜单 | `sys_menu` | 菜单/按钮树，驱动前端动态路由 + 侧边菜单 |
| 字典 | `sys_dict_type` / `sys_dict_data` | 枚举字典，前端下拉/标签统一取值 |
| 参数 | `sys_config` | 运行期可调；`configType='Y'` 为系统内置（不可删） |
| 登录日志 | `sys_login_log` | 登录成功/失败留痕，含 IP / UA |
| 操作日志 | `sys_audit_log` | 审计管道异步落库，**只读**，无删除接口 |

## 2. 关键机制

### 2.1 动态菜单 → 动态路由

`sys_menu` 同时是「菜单数据」和「路由注册表」：

```
登录 → GET /profile → GET /menu/routes（后端按权限码过滤 + 补齐祖先链）
     → 前端 import.meta.glob('../views/**/*.vue') 映射 component 字段
     → router.addRoute('layout', {...})（登出时 resetMenuRoutes 清理）
```

- `type`：`M` 目录 / `C` 菜单 / `F` 按钮（按钮只承载权限码，不渲染）。
- `component` 相对 `src/views` 且不带 `.vue`，如 `system/UserView`。
- 可见条件：`status=1 && visible=1 && type!='F' && (perms=='' || 有权限)`。
- **父链保留**：子菜单有权限、父目录没配权限码时，父链仍补齐，避免菜单丢失。

### 2.2 权限匹配唯一实现

后端 `common/authz/permission.util.ts` 的 `matchPermission()` 是**唯一实现**，
`RbacGuard` 与 `MenuService.routes()` 都用它；前端 `web_admin/src/utils/permission.ts` 同源语义。

规则：`*:*:*` 全通 → 精确 → 段末 `:*` 通配（双向）→ `!` 前缀 deny 且**优先于 allow**。

> 通用管理域的权限码全在 `system:*` 下，所以 `admin`（`*:*:*,!system:*`）对本域**全部 403**，
> 只有 `superadmin`（`*:*:*`）可用 —— 这是设计，不是缺陷。

### 2.3 幂等键的边界

`@Idempotent()` **只对 POST / PUT / PATCH 生效**：

- DELETE 语义上已幂等，强制幂等键只会让每个删除都多造一个头，收益为零。
- 前端 `request.post/put` 自动生成 `Idempotency-Key`，`request.delete` 不带。

### 2.4 级联规则

- 字典：删类型 → 级联软删其数据；改类型标识 → 事务内同步改数据的 `dict_type`。
- 菜单：改上级 → 校验不能选自己/子孙，并级联重写所有子孙 `ancestors`；存在下级时不可删。
- 参数：`configType='Y'` 不可删（可改值）。

## 3. 前端页面

组件路径写在 `sys_menu.component`（`system/UserView`、`system/RoleView`、…）。

新增业务页面时：**只加 `views/**` 组件 + 一条 `sys_menu` 记录**，不改前端路由表。
